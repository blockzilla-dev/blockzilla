# Security policy

## Report a vulnerability privately

Use [Report a vulnerability](https://github.com/blockzilla-dev/blockzilla/security/advisories/new)
to send a private report to the repository maintainers. Do not open a public
issue or pull request with exploit details, credentials or private source data.

Include the affected commit or release, a minimal reproduction, the expected
security property, and the result you observed. State whether the issue affects
stored blocks, source identity, stream authentication, recovery or resource limits.
Use synthetic data where possible and remove credentials from logs.

The maintainers will review the report and coordinate a fix and disclosure
through the private advisory. Do not publish the details before that discussion.

## Versions

The project is preparing its first 1.0 release. Report issues against the current
maintained source and name the exact revision. A support table will be added
with the first stable release. Experimental format branches are not a stable
compatibility promise.

For an ordinary bug that does not expose a security issue, use the
[public bug form](https://github.com/blockzilla-dev/blockzilla/issues/new?template=bug.yml).
